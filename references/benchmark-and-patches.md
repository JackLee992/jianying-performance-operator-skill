# 提速验证与补丁边界

独立工具仓库：[jianying-macos-performance-patches](https://github.com/JackLee992/jianying-macos-performance-patches)。只包含原创工具和研究摘要；补丁仅支持指定版本/架构/源哈希，不附厂商二进制。使用前读取该仓库 README；生产排障不默认制作或启动补丁副本。

`taskcenter` 只跳过任务完成回调的一次列表刷新，弹窗可能暂时显示旧行。已有本机 300 秒复合预合成/响度 smoke、约 248 秒成片导出、完整解码、12 帧抽查及一次原生取消验证；没有同一冷缓存工程受控提速结果。重新签名可能改变权限/插件/账号表现，官方应用保持可回退，应用副本不隔离共享偏好和工程。

两任务并行已在一个独立工程中观察到两个任务同时执行；依赖、队列所有权、去重、不同取消/重试场景与内存/GPU 竞争仍须逐项验证。普通调度每次启动一个新任务并遇活动条目返回，不证明整个程序全局最大并发为一。`task_controller_config.AB.PreCombine` 被转换为布尔启用值，不是线程数；不要改“1→4”并声称四倍提速。线程池容量也不是启动门控。

受控比较用另存的原生工程，至少两个互不依赖的长复合。源媒体可只读共享，但缓存目录必须由测试工程独立拥有，拒绝通过 symlink 到达原工程。先保存并原生复开验证，再冻结同一 fixture。每次恢复到同一 canonical 测试路径，将测试所有的派生缓存移入本轮归档；不得递归清除原工程或全局缓存。

“冷”明确限定为应用派生缓存缺失；OS page cache 未控制，应披露。新文件夹或新项目名不证明内部缓存身份改变；无法证明缓存 miss 时报告 unknown/warm。使用同一预处理/签名方式、相同弹窗可见性、输出目录、源位置、效果和导出规格，对照/候选/候选/对照各运行一轮；只有一对结果时标为 preliminary。

记录每个任务的开始/结束、总体耗时、输出最终化、缓存命中、内存、CPU、热状态和错误。视频与 alpha 为同一任务输出，不能算两个并发任务；原生不同 task ID 或不同复合输出组的单调重叠增长才支持独立任务并行。并发二不等于提速二。

完成后逐项报告：离线构建、静态验证、运行 smoke、取消/恢复、导出、受控 A/B。完整解码、时长/尺寸/流结构、抽帧/声音核对各说明范围，抽帧不能叫完整画面等价。列出全部轮次，不只最快；无改善或变慢直接报告。

## 已完成的受控准备试验与边界

一台机器上，同一独立工程的两个约 628 秒复合进行冷派生缓存 ABBA：串行均值 **267.869 秒**，两任务均值 **268.886 秒**，差 1.017 秒；没有测到提速，小样本也不支持显著变慢的统计结论。不同复合确有重叠执行，因此“调度并发已发生”与“总吞吐未提升”可以同时成立。素材在外置盘、派生缓存写内置盘，OS 页缓存未控制。各轮数据见补丁仓库 [EVIDENCE](https://github.com/JackLee992/jianying-macos-performance-patches/blob/main/EVIDENCE.md)。生产建议继续串行，优先减少已证明重复的长复合，不据此升到更多任务。

额外原生样本的主要等待落在编码提交/VideoToolbox 链，与下游编码或提交背压的假设相符。它没有区分具体编码会话、条件变量、硬件能力或其他下游限制；相同栈位置不等于同一个全局锁，也不能凭 CPU 空闲排除瓶颈。下一步若研究此处，应对齐具体任务、提交/完成事件、输出增长和等待对象，不能先修改线程数再解释结果。

取消场景 C：在开始后 76.564 秒关闭响度勾选，已经启动的准备仍继续；176.421 秒使用原生响度任务行的 X 后，下一次采样（相隔 0.826 秒）已移除目标缓存文件，同组另一任务继续。0.826 秒是采样间隔，不是精确取消延迟。稍后重试的目标任务用时 134.319 秒完成。这只支持这个单任务原生取消与稍后重试场景；**没有验收取消全部任务或取消后立即重试**。

## 两任务候选的后续导出与复开

候选完成一份约 20 分 55 秒原生导出：H.264、1080×1920、30 fps，视频时长 1255.233333 秒，音频 AAC/44.1 kHz。完整解码退出码为 0、无解码错误。这支持该输出可完整读取，不是对照视频逐帧等价或人工听检。音量统计 mean -28.4 dB、peak -2.9 dB 不是 LUFS 测量，不能据此认定最终节目达到 -23 LUFS。

保存、正常退出后原生复开一次观察为 2.202 秒，两份复合均显示 -23 LUFS 已完成。四份 Resources 视频/alpha 文件的路径、大小和纳秒 mtime 在约一分钟观察内不变。该窗口内未观察到这些文件重写；不证明所有缓存都命中、长期不会重建或首次解析加速，也不是打开速度 A/B。

准备吞吐、单项取消、完整解码和保存复开分别成立；音视频等价仍需独立验证。历史 UI-only 补丁的成片导出记录与原生分离音频的结果分别报告，不能互相代替。


共享 helper 的导出等待路径覆盖整个视频队列、未见活动成片过滤，不足以认定哪些任务无用。一次 Home/复开原生回收了 41 组实验 final-name family 中的 32 组；被回收不等于无引用。后续单次保存后正常重开只减少页头计数，观察时仍在导出准备，不能当成提速验收。保护必要缓存、限定一次重开并递归确认当前成片依赖的操作见 diagnosis reference；保留的 843 个原缓存仅有大小/mtime 未变的范围性证据。
